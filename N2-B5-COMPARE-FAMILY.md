1. **Status.** B5 COMPLETE — READY FOR NEXT ROADMAP BATCH. This is an isolated no-icons batch; A0.2/A1 remained in progress when B5 began.
2. **Starting checkpoint.** B9 was committed locally as `951c277acd32cb0da0f8be0e7c26266a4e667525` (`feat(splitter-scroll-area): complete Neural 2 resizable layout`). Its 22 files exclude the unrelated untracked TreeTable file.
3. **Compare audit.** Focused refactor: the former `internalValue` was a second applied owner, `defaultValue` was only read in the constructor, pointer capture lacked identity/cancel/destroy handling, and horizontal geometry was physical-LTR only. The numeric range contract itself was coherent.
4. **Child audits.** Handle now hosts the sole native range control and derives position from Compare. Indicator is a non-focusable presentation layer with a derived divider; projected informative content remains available to assistive technology. Item only projects before/after content and derives clipping. Neither child stores value or handles independent pointer gestures.
5. **Public API.** The four component exports, `NeuCompareOrientation`, and `NeuCompareValueChangeEvent` remain. `value`, `defaultValue`, `min`, `max`, `step`, `orientation`, `slideOnHover`, `disabled`, `valueChange`, and `valueChangeEnd` retain their names. The `ariaLabel`/`ariaLabelledBy` inputs move from Indicator to Handle, where the adjustable control actually lives; this is an intentional Neural 2 breaking delta. No alias was added. Official declaration snapshot and reconciliation were regenerated; 99 entrypoints, 793 exported declarations, 1,487 bindings.
6. **Ownership.** `value` is the applied parent input. If absent, `defaultValue` is a reactive parent-provided fallback, not an uncontrolled writable model. Interaction only emits proposals; parent acceptance changes the DOM, parent rejection leaves it unchanged. Pointer ID and last proposed drag value are ephemeral, never applied state.
7. **Value domain.** The existing numeric `min`–`max` domain is preserved (defaults 0–100, step 1), not silently changed to 0–1. Values are clamped and snapped relative to `min`; a non-finite minimum falls back to 0, a non-finite or inverted maximum collapses to minimum, and a non-positive/non-finite step falls back to 1. Parent writes recompute the percentage without output echo.
8. **Pointer.** Local root Pointer Events use capture, one active pointer ID, deduplicated drag proposals, one completion on pointerup, no completion on cancel/lost capture, and release on destroy. No document/window drag listener. Hover proposals remain opt-in through `slideOnHover`.
9. **Keyboard.** Handle's native range is focusable. Home/End target min/max; horizontal Left/Right and vertical Up/Down move one step. Handled keys prevent the browser's second value update. Each changed key issues one live and one completion event; rejected parent proposals do not move the applied range.
10. **Orientation.** Horizontal and vertical use the same applied numeric domain. Vertical minimum is at block-end, matching existing pointer semantics; the input exposes `aria-orientation`.
11. **RTL.** Horizontal minimum is at inline-start: physical right in RTL. Pointer and horizontal arrow mapping reverse physically. CSS uses `inset-inline-start` and `:dir(rtl)` for handle and clipping, while vertical is unaffected. Browser evidence checks a 20% RTL handle lies on the physical right.
12. **A11y.** One native range inside Handle provides implicit slider role and native value min/max/now. It has the user-facing accessible label, orientation, disabled state, keyboard access and visible focus treatment. Indicator has no duplicate range/control label. Compared images retain their consumer-supplied alternatives; clipping does not fabricate or duplicate names.
13. **SSR.** A real Angular 22.1.6 zoneless consumer renders horizontal LTR, horizontal RTL and vertical instances with applied labels/values and hydration annotations. No proposal or browser API is invoked during server render.
