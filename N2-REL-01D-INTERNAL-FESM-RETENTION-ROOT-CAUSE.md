# N2 REL-01D — Internal FESM retention root cause

## 1. Status

**REL-01D ROOT CAUSE FOUND — MATERIAL PACKAGE BOUNDARY CHANGE REQUIRED.** The Angular partial declarations for `NeuInitialTemporalState` and `NeuResponsiveState` are emitted beside `NeuIdGenerator` in one internal FESM. Their unannotated static `ɵfac` and `ɵprov` initializers and top-level `ɵɵngDeclareClassMetadata` calls independently keep each class live in esbuild. A real ng-packagr build that moved the two heavy services to a separate internal secondary entrypoint removed both from ID-only consumers. All productive experiments were reverted.

## 2. Starting checkpoint

Branch `v2`, HEAD `7773da735f3098070c0f496463f1c7eee092e402`. The pre-existing REL-01C changes to three audit scripts, its report, two metafiles and its boundary audit script were preserved. The unrelated untracked `projects/ui-core/tree-table/public_api 2.ts` remained byte-identical (SHA-256 `c125dde6541cf65f1936dcc6d0468c84da4391234e2a162ba10f889d1936b644`). No starting productive source change was present.

## 3. Canonical toolchain

All package builds and byte measurements used `/opt/homebrew/bin/node` 22.22.3 on Darwin arm64, zlib 1.2.12, Brotli 1.2.0. The esbuild package was the workspace installation; minified ESM kept Angular, CDK and RxJS external. gzip used level 9; Brotli used quality 11. The audit script records the exact inputs and options. No baseline was rewritten.

## 4. Minimal NeuIdGenerator reproduction

Consumer: `import { NeuIdGenerator } from '@neural-ui/core/internal'; export const ID_GENERATOR = NeuIdGenerator;`. Resolution used the built package export map, not workspace TypeScript. The package-only input check saw compiled `foundation`, `internal` and `option-api` FESMs, with no `projects/ui-core` source input. Direct import of the internal FESM gave the same result.

## 5. Minimal bundle bytes

Baseline: **5,847 raw / 1,852 gzip / 1,615 Brotli bytes**. The real heavy-service secondary-entrypoint build: **2,426 / 806 / 696**, saving **3,421 / 1,046 / 919**. The virtual split yielded the same 2,426 raw bytes, with 809 gzip / 691 Brotli; compression changes reflect different generated bytes and do not change the retention conclusion.

## 6. Retained-symbol inventory

The baseline minified ID-only output contains `neu-temporal-state-` and `matchMedia`, despite neither being used by the consumer. It also carries the temporal service's transfer-state/timezone path and the responsive service's browser media-query path. Both markers disappear after the real heavy-service split. The FESM itself is 53,048 bytes and 1,370 lines; the bundle retains only a subset, not the whole FESM.

## 7. Compiled internal FESM structure

`dist/neural-ui/core/fesm2022/neural-ui-core-internal.mjs` begins with imports from Angular common/core and `foundation`/`option-api`, then declares `NeuIdGenerator` at line 8, `NeuInitialTemporalState` at line 23 and `NeuResponsiveState` at line 77. It ends with a common generated export list for these and other internal helpers. There are four class-metadata calls in the FESM: these three classes and `InternalNeuOverlayStack`. There are no `@__PURE__` annotations in this emitted file.

## 8. Angular generated metadata

`NeuInitialTemporalState` has `static ɵfac` at line 69, `static ɵprov` at line 70 and a top-level `i0.ɵɵngDeclareClassMetadata(...)` at line 72. `NeuResponsiveState` has the corresponding expressions at lines 144, 145 and 147. `NeuIdGenerator` has the same declaration family. These are Angular partial-compilation declarations emitted by ng-packagr's Angular compilation stage, not handwritten calls in the source.

## 9. Top-level side-effect analysis

The package declares JavaScript entrypoints side-effect-free through `sideEffects: ["./styles/*.scss", "./styles.scss"]`. That metadata lets esbuild discard unused *modules* but does not prove that an expression inside a retained FESM is pure. Static class field initializers call Angular declaration functions during module evaluation; class-metadata calls also execute at top level. The class references inside those calls keep the class definitions and their instance-method code reachable. No temporal or responsive constructor is shown to run merely because the module loads; the measured cost is code retention.

## 10. Exact retention witness

Each heavy class has **three independent witnesses**, not one: its `ɵfac` initializer, `ɵprov` initializer and class-metadata call. Removing any two of the three still retains that class's marker. Removing all three for the temporal class drops `neu-temporal-state-` (5,847 → 4,153 raw); doing so for the responsive class drops `matchMedia` (5,847 → 4,268 raw). Removing all six drops both (→ 2,574 raw). This is a diagnostic deletion only: it breaks Angular declarations and is not a remediation.

## 12. Rollup/ng-packagr attribution

The TypeScript source puts all three services in `neu-hydration-internals.ts`; ng-packagr/Rollup emits them into one APF FESM and Angular emits the partial declarations above. REL-01C's real build split ID into a second **source** file but kept the same `internal` entrypoint and the same 46,636/63,004 raw Kanban/ColorPicker bundles. Esbuild then retains the emitted declarations. The successful real REL-01D build made a second **package entrypoint/FESM**, proving that package emission topology, rather than a flag in the final esbuild run, is the effective boundary.

## 13. AST/declaration bisection

Virtual on-load FESM copies removed one declaration family at a time; the installed `dist` file was never edited. Removing temporal `ɵfac` only gave 5,687 raw, `ɵprov` only 5,719, metadata only 5,677; the temporal marker remained. Removing any two still retained it (5,517–5,558 raw). The responsive class behaved analogously (5,543–5,575 raw with two removed). Full class-family deletion, rather than a method-body edit, is the first tested operation that makes each marker disappear. The test is causal evidence about reachability, not a safe patch.

## 14. Pure-annotation experiments

Annotating metadata calls alone gave 5,681 raw for temporal and 5,393 raw for all class metadata, but both markers remained. Annotating all three declaration calls for all three classes also gave 5,393 raw and retained both markers. Esbuild's `pure` option naming Angular declaration calls gave the baseline 5,847 raw. These annotations do not solve static class-field reachability in this emitted shape; adding them to generated output would also be an unsupported build transformation.

## 15. Source dependency graph

`NeuIdGenerator` needs Angular injectable metadata and a `Map`; it has no source reference to temporal or responsive state. `NeuInitialTemporalState` uses `TransferState`, platform/app IDs, `NEURAL_NOW` and `NEURAL_TIME_ZONE` from foundation. `NeuResponsiveState` uses Angular signals/effects and browser `matchMedia` behind `afterNextRender` and `isPlatformBrowser`. The shared edge is the `internal` entrypoint/FESM, not a call from ID generation to those services. The 40 consumers import `@neural-ui/core/internal`; secondary FESMs import its named symbols.

## 16. Barrel/re-export experiments

The internal barrel's re-export of an ID class moved to a separate virtual FESM **did not** remove heavy code: the ID-only probe became 5,949 raw, with both markers. A real narrow-ID build that left the old `internal` import path in place similarly gave 5,922 raw. Re-exporting heavy services *out* of internal through a new entrypoint did work: the real ID-only probe became 2,426 raw. Directly rewiring component imports to a narrow ID entrypoint also worked, but requires changing the consumers.

## 17. Why source-file split produced 0 raw saving

Rollup flattened the new source file back into `neural-ui-core-internal.mjs`. The same three injectable classes and generated declaration expressions remained in one module. Esbuild's tree-shaking input and reachable top-level expressions were therefore unchanged. REL-01C's measured 0 raw saving is reproduced mechanistically by this audit.

## 21. Multi-component/application cost

The same virtual deletion proxy saved 2,977 raw bytes in a composed Kanban+ColorPicker namespace bundle (104,033 → 101,056), 2,985 bytes across five ID-only entrypoints, 2,985 across ten, and 3,001 across all 36 ID-only entrypoints. ## 23. Foundation experiment

## 24. Narrow-entrypoint experiment

## 25. Heavy-side relocation experiment

A real temporary `internal-state` secondary entrypoint contained both heavy injectables; `internal` re-exported their names. All existing consumer imports remained unchanged. ng-packagr built the entrypoint successfully. ## 26. Primitive/service-facade experiment

Moving the primitive/facade to a separate package entrypoint becomes the narrow-entrypoint option above. An undecorated class alone would change `providedIn: 'root'` behavior and was not presented as a valid fix.

## 29. DI implications

`NeuIdGenerator` must remain one root-scoped injectable so IDs remain deterministic per injector. Both heavy services must keep their `providedIn: 'root'`, `ɵfac` and `ɵprov` declarations and retain the same class identity through internal re-exports. The heavy-side experiment preserved decorators in source and built; it did not run injector identity tests. A production implementation needs directed tests for cross-entrypoint injection and shared injector identity before acceptance. Declaration deletion and undecorated-class probes are diagnostic only.

## 30. SSR/hydration implications

Temporal state must still read/write `TransferState` with `APP_ID`, `NEURAL_NOW` and timezone on server/client; responsive state must still defer browser media-query work until after render and guard with `isPlatformBrowser`. The heavy-side candidate moves module location, not method bodies. The package build and bundle markers prove emission/reachability only, not runtime hydration equivalence; directed SSR/hydration tests remain a required implementation gate.

## 31. Complexity/maintenance comparison

Recommended: heavy-side relocation, because it changes one source ownership boundary and preserves 40 consumer imports and the root-DI contract. Narrow ID has larger isolated Kanban/ColorPicker savings but needs broad import migration and a permanent second internal contract; components that also need other internal helpers will still load `internal`. Foundation move has no new export path but exposes ID in the supported foundation API and taxes unrelated consumers. Source-only/facade options fail the observed retention mechanism. All three successful real-build candidates require maintaining package entrypoint rules and build graph ordering; heavy-side has the smallest consumer migration burden.
