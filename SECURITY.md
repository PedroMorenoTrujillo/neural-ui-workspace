# Security policy

## Supported releases

Security fixes are made on the latest published Neural UI release. Older releases may receive a backport when the change is low risk, but backports are not guaranteed. Consumers should keep Angular, Angular CDK and Neural UI on supported versions listed in [SUPPORT.md](./SUPPORT.md).

## Private reporting

Do not disclose an unpatched vulnerability in a public issue. Use the repository's [private security advisory form](https://github.com/PedroMorenoTrujillo/neural-ui-workspace/security/advisories/new) and include:

- affected Neural UI and Angular versions;
- reproduction steps or a minimal repository;
- expected impact and required privileges;
- any suggested mitigation, if known.

If GitHub does not offer the private form, open a public issue containing no exploit details and ask the maintainer to establish a private channel.

Reports are handled by the maintainer on a best-effort basis. Receipt, triage and remediation times are recorded in the private advisory, but this community project does not promise a response or resolution SLA.

## Disclosure

The maintainer and reporter should coordinate disclosure after a fix or mitigation is available. Security releases document affected versions, remediation and credit when the reporter wants attribution. No paid certification or disclosure service is required.
